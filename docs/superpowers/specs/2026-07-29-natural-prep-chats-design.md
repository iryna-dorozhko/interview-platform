# Природні prep-чати: дизайн

**Дата:** 2026-07-29
**Статус:** Затверджено в brainstorming

## Контекст

Три prep-агенти (Candidate Agent, Company Agent, Company Profile Agent) мають промпти, написані як технічні інструкції. Це створює дві проблеми:

1. **Тон** — агенти звучать формально й механічно: «Я AI-асистент», жорсткі переходи між темами, довгі відповіді.
2. **Структура** — фіксований порядок тем (Досвід → Сильні сторони → ...) робить розмову схожою на анкету, а не на живий діалог.

## Рішення

Переписати system prompt усіх 3 prep-агентів:
- Змінити тон на «кар'єрний коуч» — емпатичний, лаконічний, цілеспрямований.
- Замінити фіксований порядок тем на гнучку навігацію: чеклист тем для покриття, порядок — на розсуд агента за контекстом розмови.

Зміни торкаються **тільки промптів** (`backend/src/agents/prompts/*.uk.ts`). Код агентів, parsing READY-маркерів, extraction, UI — без змін.

## Scope

### In scope
- Переписати 3 промпти: `candidate-agent.uk.ts`, `company-agent.uk.ts`, `company-profile-agent.uk.ts`
- Оновити тести, які перевіряють конкретний текст промптів (якщо такі є)

### Out of scope
- Live-агенти (arbiter, company-live, candidate-live) — окремий етап
- Decision/decline letters
- Extraction prompts
- UI-компоненти
- Backend logic (agent runners, parsing, socket handlers)

## Архітектура змін

### Загальні принципи тону (всі 3 агенти)

| Аспект | Зараз | Буде |
|---|---|---|
| Самоідентифікація | «Ти — AI-асистент, який проводить структуроване інтерв'ю» | Персона коуча/консультанта, без слова «AI-асистент» |
| Опис мети | «зібрати профіль перед співбесідою» | «коротка розмова, щоб краще зрозуміти тебе/вакансію/компанію» |
| Довжина відповідей | Не обмежена — агент часто пише есе | «2-4 речення, як у месенджері» |
| Реакція на відповідь | Одразу наступне питання | Спочатку коротка реакція на сказане, потім питання |
| Переходи між темами | «Тепер перейдемо до...» | Органічно: «Ти згадав X — розкажи більше» |
| Стиль промпту | Інструктивний (правила для робота) | Описовий (хто ти, як спілкуєшся) |

### Гнучка навігація по темах

**Механізм:**
1. Промпт містить чеклист тем, які потрібно покрити (ті самі теми, що й зараз).
2. Агент обирає наступну тему органічно, залежно від контексту розмови.
3. Якщо людина сама згадує тему з іншого блоку — агент підхоплює й розкриває її зараз, а не каже «до цього дійдемо пізніше».
4. Перед READY:true агент перевіряє, чи всі теми покриті; якщо щось пропущено — природно повертається: «Ми ще не говорили про X — розкажи коротко».

**Обмеження:** Порядок гнучкий, але набір тем — фіксований. Агент не може пропустити тему (окрім випадків явної відмови людини, як із зарплатою).

### Candidate Agent — деталі

**Персона:** Кар'єрний коуч, який допомагає підготуватися до співбесіди. Говорить на «ти», тепло, але по справі.

**Вітання:** Без «Я AI-асистент». Просто: привітання + пояснення мети + перше питання (ім'я).

**Блок знайомства:** Залишається (ім'я, email, телефон), але м'якше. Після отримання імені — перехід до тем профілю.

**Теми (чеклист, порядок гнучкий):**
- Досвід (ролі, роки, ключові проєкти, технології)
- Сильні сторони (навички + приклади)
- Зони росту (конструктивно)
- Умови роботи (формат, зарплата, графік, релокація)
- Кар'єрні цілі (напрямок, тип продукту/команди)

**Правила follow-up:** Залишаються без змін — конкретика замість абстракцій, один розкритий кейс на тему.

**Правила по імені:** Залишаються — вибіркове звертання, не в кожному повідомленні.

**READY:true критерії:** Без змін.

### Company Agent (vacancy prep) — деталі

**Персона:** Досвідчений HR-консультант, який допомагає описати вакансію так, щоб знайти найкращого кандидата.

**Вітання:** Без «AI-асистент, який проводить структуроване інтерв'ю». Привітання + мета + перше питання (яку роль шукаєте?).

**Теми (чеклист, порядок гнучкий):**
- Посада (назва, рівень, команда)
- Вимоги (критичні + бажані)
- Очікування (перші місяці)
- Умови (зарплата, формат, графік, бенефіти, релокація, випробувальний, обладнання)

**Підтеми умов:** Теж гнучкий порядок — якщо HR сам згадав бенефіти, не чекати черги.

**READY:true критерії:** Без змін.

### Company Profile Agent — деталі

**Персона:** Консультант, який допомагає створити привабливий образ компанії для кандидатів.

**Вітання:** Привітання + мета + перше питання (назва компанії).

**Теми (чеклист, порядок гнучкий):**
- Назва компанії
- Культура
- Напрямок (галузь, продукт, місія)
- Політики (відпустки, бенефіти, правила)
- Формат роботи
- Онбординг

**READY:true критерії:** Без змін.

## Що НЕ змінюється

- **READY:true/false маркер** — невидимий для юзера, потрібен системі
- **Критерії READY:true** — ті самі для кожного агента
- **Правило одного питання за раз**
- **Правило «не вигадуй факти»**
- **Обробка порожнього повідомлення** (автовітання)
- **Код агентів** (runners, parsing `parseAgentReply()`, extraction prompts)
- **Frontend** (chat panels, composables, socket handlers)
- **Мовне обмеження** (українська) — залишається, але менш агресивне формулювання

## Тестування

- Запустити кожен prep-чат вручну й перевірити:
  - Тон: чи звучить як коуч, а не як анкета
  - Гнучкість: чи підхоплює тему, якщо людина її згадує поза чергою
  - Повнота: чи покриває всі теми перед READY:true
  - READY:true/false: чи коректно парситься маркер
- Прогнати існуючі unit-тести (формат відповіді, READY-маркер)

## Ризики

1. **Гнучка навігація може пропустити теми** — мітигація: інструкція «перед READY:true перевір чеклист, дозбери пропущене».
2. **Коротші відповіді можуть здаватися поверхневими** — мітигація: правила follow-up залишаються, агент занурюється в деталі коли потрібно.
3. **Зміна тону може зламати extraction** — мітигація: extraction працює по стенограмі, не по промпту; формат реплік не змінюється.
